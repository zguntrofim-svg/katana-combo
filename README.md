## 0.11.0 — исправлена активация блока на сервере
Причина: клиентский UseItemCallback возвращал CONSUME. Fabric API 0.116.18 отправляет пакет interactItem из этого callback только при SUCCESS. Поза включалась локально, но сервер не получал запрос на блок.
Теперь клиент возвращает SUCCESS (Fabric отправляет обычный пакет), сервер возвращает CONSUME после регистрации защиты. Механика урона сохранена: обычный фронтальный блок пропускает 40%, идеальное парирование отменяет один подходящий удар в первые четыре серверных тика. Вторая рука должна быть пуста.
Обновите клиент и сервер. Выполнена только сборка JAR; игра и тесты по ранее заданному ограничению не запускались. Исправление основано на чтении обработчиков Fabric ClientPlayerInteractionManagerMixin и ServerPlayerInteractionManagerMixin.

# Katana Combo 0.11.0 — Fabric 1.21.1

Нужны Java 21, Fabric Loader >= 0.16.10 и Fabric API 0.116.18+1.21.1.
Установите JAR в mods клиента и сервера. В одиночной игре используется встроенный сервер.
Мод действует на все SwordItem в основной руке. Топоры и другие предметы работают как раньше.
На сервере без этого мода клиент сохраняет ванильные атаки.

## Управление
Каждый удар — отдельное нажатие ЛКМ по воздуху или существу.
1. Горизонтальный: 10 тиков, попадание на тиках 3–5, урон x1.
2. Обратный диагональный: 12 тиков, попадание на тиках 4–6, урон x1.
3. Сверху вниз: 16 тиков, попадание на тиках 6–8, урон x1.5, отбрасывание 0.4.
20 тиков = 1 секунда при нормальной скорости сервера.
Следующий удар можно заказать в последние 4 тика текущего удара, очередь максимум 1.
После завершения есть 18 тиков (0.9 секунды) на продолжение. После третьего начинается новая серия.
Клики раньше окна очереди игнорируются. Удержание кнопки не повторяет комбо.
При наведении на блок сохраняется обычная добыча; комбо этим кликом не начинается.
Смена предмета, смерть, смена измерения или использование предмета отменяет серию.

## Проверка в игре
- В творческом мире возьмите меч, вызовите прочного моба без ИИ и бейте отдельными кликами.
- Проверьте три удара, усиленный третий, паузу более 0.9 сек после завершения и новую серию.
- Попробуйте спамить ЛКМ: урон не должен дублироваться или ускоряться.
- Уберите цель за стену и дальше 3 блоков: попаданий быть не должно.
- Проверьте группу мобов спереди и моба сзади. Каждый фронтальный моб поражается максимум раз за удар.
- Проверьте смену слота во время подготовки, смерть, телепорт между измерениями.
- Разрушайте блоки мечом и киркой; бейте топором: ванильное поведение должно сохраняться.
- Подключите второй клиент, проверьте наблюдение атаки, в том числе вход в область отслеживания во время удара.
- На сервере отключите PvP и проверьте, что игроки не получают урон от комбо.

## Анимации
Встроенные анимации рисуются процедурно через ванильную модель.
Клиентский адаптер регистрируется в ComboClient.ANIMATION.
update(UUID, Identifier, elapsedTicks, durationTicks) вызывается каждый клиентский тик.
ID: katana_combo:horizontal, katana_combo:reverse_diagonal, katana_combo:overhead.
null вместо ID означает остановку. Событие приходит для себя и отслеживаемых игроков.
Можно подключить собственный рендерер без новой библиотеки. Серверные тайминги задаёт ComboTiming.

## Ограничения первой версии
Сектор удара: до 3 блоков, угол 120 градусов в 3D по направлению взгляда, проверка видимости.
Урон использует атрибут GENERIC_ATTACK_DAMAGE и стандартную обработку damage (броня, щит, сопротивление).
Ванильные критические удары, sweep, бонусы зачарований и полная логика PlayerEntity.attack здесь не воспроизводятся.
Оружие изнашивается при успешных попаданиях. Библиотек анимации не добавлено.
Визуальные следы клинка с референса пока отсутствуют.

## Совместимость
Проверены fabric.mod.json и имена mixin-конфигураций всех 11 предоставленных JAR.
Боевых модов среди них нет. Декларируемых конфликтов с katana_combo не найдено.
Sodium 0.11.03 допускает MoreCulling 1.0.11; максимальное требование Loader в наборе — 0.16.10.
Это статическая проверка, не доказательство совместимости при запуске полной сборки.
Better Combat и Epic Fight явно запрещены метаданными: одновременная замена атак требует отдельного адаптера.
Другие не предоставленные боевые моды не проверены.

## Сборка
./gradlew build
./gradlew runClient
./gradlew runServer
check включает ComboTimingCheck (границы сброса, порядок ударов, очередь и окна попаданий).

## Файлы
build.gradle, settings.gradle, Gradle wrapper — сборка.
ComboMod.java — серверные состояния, проверка попаданий, отключение ванильной атаки, рассылка.
ComboTiming.java — тайминги, урон и переходы серии.
ComboPackets.java — два сетевых сообщения.
ComboClient.java — отправка ввода и события анимации.
MinecraftClientMixin.java — перехват ЛКМ без перехвата добычи блоков.
fabric.mod.json и katana_combo.client.mixins.json — регистрация мода.
ComboTimingCheck.java — исполняемая проверка логики.
